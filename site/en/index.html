Every tool takes product (gen or civil), and the AI picks which one to use. Each tool is described in the README and llms.txt.

How it works

AI app (Claude Desktop, ...)→ midas-nx-mcp (your PC)→ Gen NX / Civil NX (same PC)

Everything runs on your PC. The AI app starts and stops the server; you never run it yourself.

Requirements

What you need

OSWindows
NXGen NX or Civil NX running on the same PC, with its Open API connected (Apps > API Settings)
MAPI keyOne per product, shown under Apps > API Settings in each program. Use your own PC's key.
AI appClaude Desktop, latest version (recommended). Claude Code, Codex, Gemini CLI and other MCP clients work too.

Do not swap the Gen and Civil keys. The other product's key still reports "connected", but every real call fails. Do not share your key with anyone.

Install

Install: Claude Desktop

No Python or uv to install.

  1. Download

    Get midas-nx-mcp-<version>.mcpb from the latest release.

  2. Open it

    Double-click the file, or drag it onto Settings > Extensions in Claude Desktop.

  3. Enter your keys

    Enter the Gen and Civil keys; leave the one you do not use empty. The output folder (default C:\temp, which must exist) and the analysis timeout are set here too. Change them later under Settings > Extensions.

  4. Check the connection

    Open a model in NX and ask Claude "Check the Gen connection". If it reports connected and the program name, you are done.

Other apps / by hand

These need uv. Install it once from PowerShell:

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

Open claude_desktop_config.json with Settings > Developer > Edit Config, add the server under mcpServers, then quit Claude Desktop completely (tray icon too) and start it again.

{
  "mcpServers": {
    "midas-nx": {
      "command": "uvx",
      "args": ["midas-nx-mcp@latest"],
      "env": {
        "MIDAS_MAPI_KEY_GEN": "your Gen NX key",
        "MIDAS_MAPI_KEY_CIVIL": "your Civil NX key"
      }
    }
  }
}
claude mcp add midas-nx -e MIDAS_MAPI_KEY_GEN=your-gen-key -e MIDAS_MAPI_KEY_CIVIL=your-civil-key -- uvx midas-nx-mcp@latest

Add this to ~/.codex/config.toml, or add a STDIO server in the settings screen.

[mcp_servers.midas-nx]
command = "uvx"
args = ["midas-nx-mcp@latest"]
env = { MIDAS_MAPI_KEY_GEN = "your Gen NX key", MIDAS_MAPI_KEY_CIVIL = "your Civil NX key" }

Add this to %USERPROFILE%\.gemini\settings.json. Then run gemini in the folder you will work in and trust it: in an untrusted folder the server stays Disabled. /mcp shows whether it is connected.

{
  "mcpServers": {
    "midas-nx": {
      "command": "uvx",

Signing in to Gemini: a Google AI Pro or Ultra subscription, or a company Gemini Code Assist Standard or Enterprise account, uses Login with Google. A free personal account is refused there with IneligibleTierError; get an API key from Google AI Studio, set it as GEMINI_API_KEY, and choose Gemini API Key as the sign-in method.

At most 200 rows come back at once. For more, ask for a range: "the next 200", "only 1001 to 1100".

Safety

Preview → confirm → apply

Anything that changes the model or its file (analysis, save a copy, create / update / delete records) takes two steps. The AI shows what will change first and applies it only after you say "go ahead". If the model changed in between, it is refused; afterwards the table is read back and reported.

  • Any change discards the analysis results. Run the analysis again before reading results.
  • NX saves over the open file before it analyses. To keep the original, ask for "save a copy" first.
  • A document that was never saved cannot be analysed. Save a copy first to give it a file.
  • Copies go to C:\temp under a generated name, and NX then works on the copy.
  • New / open / import document and emptying a table are never offered: they are too risky.
Add a node at (4, 3, 0) in Gen
Preview · NODE 13 will be created. Analysis results will be discarded. Go ahead?
Go ahead
Applied · NODE 13 added (read back to confirm)

Try it on a copy of an important model first. This alpha has been verified on small test models, not yet on large production models.

Troubleshooting

Troubleshooting

SymptomCheck
Every call suddenly times outLook for a dialog in NX and answer it in the NX window. Do not ask the AI to retry.
"... is not set"That product's key is entered (Settings > Extensions)
Connected, but reads failThe Gen and Civil keys are not swapped, and NX's API is connected
"NX is not running"Start NX and connect under Apps > API Settings
"no analysis result"No analysis yet, or a later change discarded the results
Capture or save failsThe output folder (C:\temp) exists
